端智能日报 2026-05-14

本期聚焦：Apple 以"端侧私有数据不离设备"为技术底座，正式推动 Apple Maps 广告上线（iOS 26.5 已铺路，夏季正式发布），同步扩大 Apple Ads 团队主动拓客——隐私优先的端侧广告定向机制正成为后 ATT 时代的新范式；Google LiteRT 生态系则在同期完成从"开发者预览"到"产品级量产"的跨越，NPU 统一接口推动 Google Meet 25× 大模型零延迟上线、Epic MetaHuman 在安卓 30 FPS 实时运行。

1. 【iOS 26.5 Apple Maps广告 + Apple Ads扩张团队：端侧私有数据驱动的场景广告新范式】

  • 评分：A/4 · I/4 · S=12 · P0 · 价值类型：新能力探索 / 用户体验
  • 来源：9to5Mac | Apple Maps is launching ads soon | 2026-05-13；新浪科技 | 苹果加码广告业务，组建新团队主动拉拢开发者投放 | 2026-05-14

内容总结（~140 字）： iOS 26.5（2026-05-11 正式发布）已为 Apple Maps 广告完成底层适配，夏季在美国和加拿大正式上线。广告位仅两处：搜索结果顶部 + "Suggested Places"推荐列表，均以蓝色背景 + "Ad"标识明确区隔。核心技术：全程端侧定向——设备本地依据"当前粗略位置 + 搜索词"计算广告相关性，不与 Apple Account 关联，不上传至 Apple 服务器，不向第三方共享；无长期用户画像，每次请求即用即弃。同日，苹果 Apple Ads 部门组建 Emerging Team，开始主动联系开发者恢复/新建投放，并提供关键词策略支持——苹果广告生态从"等客上门"转向主动运营。收入预测（Truist 模型）：2026 广告收入 <1B 美元，2030 目标 30B+。

业务价值与适配性： 可以让我们在 Apple Maps 正式开放后，将地图广告纳入多平台广告库存矩阵，为商户 LBS 广告提供 Apple 用户侧触达路径，补充当前 Google Maps 单一依赖。更重要的是，Apple 的端侧隐私定向机制（"当下语境"替代"历史画像"）为我们在 ATT 合规约束下的端侧 CTR 推理提供了重要范式参考：可借鉴"仅用当次上下文特征 + 端侧实时推断"的设计思路，重构端侧 CTR 特征工程，减少对跨请求持久化 ID 的依赖。可直接应用：待 Apple Ads API 开放后，优先评估将 Apple Maps 广告集成进移动端广告 SDK 的可行性；方法论上，建议将 Apple 端侧定向机制列入隐私广告架构评审的参考案例。

2. 【Google LiteRT NPU 全面落地：Google Meet 25× 大模型零延迟 + Epic MetaHuman 安卓 30 FPS 实时渲染】【延迟发酵】

  • 评分：A/3 · I/4 · S=10 · P1 · 价值类型：成本优化 / 新能力探索
  • 来源：Google Developers Blog | Building real-world on-device AI with LiteRT and NPU | 2026-04（延迟发酵，近期 Google I/O 生态预热内容）

内容总结（~130 字）： Google 通过两个生产级案例宣告 LiteRT NPU 从"早期访问"升级为全用户正式可用。① Google Meet：移动端 NPU 部署超高清背景分割模型，新模型比旧版大 25×，推理速度不变，功耗和热量控制维持同等水平；② Epic Games Live Link Face（Android）：基于 LiteRT NPU 实现实时面部捕捉驱动 MetaHuman 3D 动画，30 FPS 稳定运行；③ Argmax SDK：NPU 加速语音识别，在多款主流 SoC 上达到实时速度。技术核心：LiteRT 提供统一 NPU 抽象接口，兼容 Qualcomm/MediaTek/Samsung 等主流 SoC，自动处理厂商差异与 fallback，开发者无需维护多份 SoC 专属代码。单次编译，多设备运行。

业务价值与适配性： 可以让我们在广告 SDK 的端侧推理模块中以 LiteRT NPU 统一接口替代厂商专属 NPU SDK，一套代码覆盖 Qualcomm/MediaTek/Samsung 三大 SoC，维护成本大幅降低。Google Meet 25× 大模型零延迟上线的案例表明，NPU 有能力承载比当前广告端侧模型大得多的推理负载（当前端侧 CTR 模型通常 ≤ 100M 参数，NPU 可承载 500M+ 级别）。可借鉴思路：以 LiteRT NPU 为基础设施，设计广告端侧推理"三级性能档"——CPU（低端机兜底）/ GPU（中端机）/ NPU（旗舰机），同一模型不同 backend，延迟和功耗差距可达 3-5×；建议在 Android 14+ 旗舰设备上优先启动 NPU backend 实验。

3. 【LiteRT-LM 开源：端侧 LLM 推理框架量产，Gemma 4 E2B <1.5 GB 运行 + Chrome / Pixel Watch 已上线】【延迟发酵】

  • 评分：A/3 · I/4 · S=10 · P1 · 价值类型：成本优化 / 新能力探索
  • 来源：Google Developers Blog | On-device GenAI in Chrome, Chromebook Plus, and Pixel Watch with LiteRT-LM | 2026-04-07；Bring state-of-the-art agentic skills to the edge with Gemma 4 | 2026-04-02（延迟发酵）

内容总结（~140 字）： Google 开源 LiteRT-LM——基于 C++ 的端侧 LLM 完整推理管道，集成 KV cache 管理、session cloning、prompt caching、constrained decoding（结构化输出）、单模型跨 CPU/GPU 动态上下文调度。已量产：Chrome 内置 AI API、Chromebook Plus 标签管理 / 文本功能、Pixel Watch Smart Reply 均由 LiteRT-LM 驱动 Gemini Nano。Gemma 4 E2B 端侧指标：INT2/INT4 + Per-Layer Embeddings（PLE）技术实现 <1.5 GB 内存运行；4,000 input tokens 内的 agentic 任务（2 个连续技能）< 3 秒完成；跨平台：Android / iOS / Windows / Linux / macOS / Raspberry Pi 均支持。额外亮点：FunctionGemma 270M——专为端侧 function calling 优化的轻量模型（270M 参数），支持离线 App 控制和多步骤 Agent 任务，Google AI Edge Gallery（Android + iOS 均上线）可直接体验。

业务价值与适配性： 可以让我们在广告 SDK 中以 LiteRT-LM 作为端侧 LLM 统一推理后端，借助 Google 在 Chrome/Pixel Watch 量产验证的稳定性直接投入测试，避免自建 LLM 推理管道的长期维护成本。具体落地路径：① 用 Gemma 4 E2B（<1.5 GB）替代当前端侧意图识别方案，在旗舰机上完成"搜索词 → 用户意图" LLM 级推断；② FunctionGemma 270M 的 function calling 能力可驱动端侧广告策略调度（如根据用户指令动态过滤广告类目），延迟极低；③ constrained decoding 保证结构化 JSON 输出，直接对接 CTR 特征工程管道。适配性判断：建议基于 Pixel 9 或 Galaxy S25 搭建 LiteRT-LM PoC，下周 Google I/O（5/19）后评估 AICore Developer Preview API 与 LiteRT-LM 的集成深度。

4. 【百度 Create 2026：李彦宏提出"日活智能体数（DAA）"时代宣言，AI Infra 全栈布局亮相】

  • 评分：A/2 · I/3 · S=7 · P2 · 价值类型：新能力探索
  • 来源：新浪科技 | 李彦宏称 AI 时代度量衡是日活智能体数（DAA） | 2026-05-13；百度现在更像一家 AI Infra 公司 | 2026-05-13

内容总结（~120 字）： 百度 Create 2026 AI 开发者大会（5/13-14，北京）以"万物一体"为主题，核心观点集中在李彦宏的主题演讲：提出 DAA（Daily Active Agents，日活智能体数） 作为 AI 时代的新度量衡，对标移动互联网时代的 DAU——意味着百度认为 AI 价值评估应从"Token 消耗"转向"自主完成任务的智能体规模"。产品层面：文心 5.1（5/9 发布）文本榜 + 搜索榜国内第一；发布 DuMate（通用 Agent）、秒哒（代码 Agent）、百度一镜（数字人 Agent）、伐谋（自我演化决策 Agent）四类智能体。战略层面：百度智能云主打 "AI Infra + Agent Infra"双核，从"搜索公司"向"AI 基础设施公司"转型，端云协同以"芯-云-模-体"全栈布局呈现。边缘/端侧内容：飞桨（PaddlePaddle）端侧推理引擎（Paddle Lite）具体新进展待后续专题论坛报道跟进。

业务价值与适配性： 可以让我们将"DAA"框架引入广告 AI 效果评估体系——思考广告系统中"自主完成购买任务的 Agent"数量而非点击量，作为未来 AI 广告效果的前瞻性指标。暂不适用（主链路）：本次 Create 2026 的核心内容聚焦于云端 Agent 和 AI Infra，端侧推理（Paddle Lite）具体新进展未公开发布，建议关注后续专题论坛报道；DAA 概念对广告系统的长期架构影响值得内部讨论，但短期内无直接技术落地点。

其他观察

今日三条信号勾勒出端智能广告技术演进的两条平行轨道：① 隐私优先广告——Apple Maps 端侧定向机制（无持久画像、即时上下文）正在确立后 ATT 时代的行业参考标准，广告系统从"云端用户画像"向"端侧当下语境"迁移的趋势不可逆；② 推理基础设施成熟化——Google LiteRT 生态系（NPU 统一接口 + LiteRT-LM + Gemma 4 E2B <1.5GB）标志着端侧 LLM 推理从"开发者玩具"进入"产品级工程基础设施"阶段，广告 SDK 集成端侧 LLM 推理的技术壁垒已大幅降低。
