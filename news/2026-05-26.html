本期聚焦：两条主线驱动：广告算法精准化与端侧框架工程化。阿里妈妈在 WWW 2026 提出 READER 级联延迟反馈框架，直接解决后链路 CVR 建模中转化与退款双重时延问题；Influence Function 方法为延迟反馈再训练提供高效工程路径。Google I/O 2026（5月19日）LiteRT-LM 正式 GA，配合 Qualcomm QNN Accelerator，56 款模型在旗舰 NPU 上推理 <5ms，Android 广告端侧推理进入新基准线。

1. 【WWW 2026 | 阿里妈妈 READER：级联延迟反馈建模新框架，直击展示广告 CVR 后链路痛点】

  • 评分：A5/5 · I4/5 · S=14 · P0 · 价值类型：收入提升
  • 来源：阿里妈妈 / ACM Web Conference 2026 | arxiv.org/abs/2601.20307 | 2026-01（WWW 2026 收录）

内容总结（约 140 字）： 阿里妈妈联合团队在 WWW 2026 发表 READER 框架，聚焦"级联延迟反馈"(Cascaded Delayed Feedback, CDF) 问题——展示广告中，转化(conversion)和退款(refund)均存在时延且顺序依赖，双重延迟导致训练数据严重失真，传统 DFM 方法只处理单步延迟、无法覆盖此场景。READER 核心：① 双专家塔架构分别建模转化路径与退款路径；② 去偏模块（label calibrator + 部分标签遗忘策略 partial label unlearning），纠正训练时可见标签与最终标签的分布偏差。生产场景：阿里妈妈展示广告（淘天平台），是与 TESLA 流式延迟反馈框架配套的后链路精细化模块。

业务价值与适配性： 可以让我们在广告 CVR/后链路转化预估场景下，将「有延迟转化标签」的样本损失降至最低，尤其适合有退款/撤单逻辑的电商 & 泛直播广告。可直接应用（CVR 模型训练数据处理模块）：双专家塔 + label calibrator 架构可落地到现有 Post-Click 模型训练流水线；partial label unlearning 可缓解训练/服务标签分布偏移，预计可有效提升 AUC 与线上 CVR 正相关度。P0：可直接立项参考，代码复现周期 1-2 周。

2. 【Delayed Feedback Modeling with Influence Functions：用影响函数高效修正延迟转化偏差，免全量重训练】

  • 评分：A5/5 · I3/5 · S=13 · P1 · 价值类型：成本优化 + 收入提升
  • 来源：arXiv | arxiv.org/abs/2502.01669 | 2026-02

内容总结（约 130 字）： 针对广告延迟反馈建模的工程痛点——延迟标签到达后需重新训练模型，成本极高——本文引入 Influence Functions 实现高效增量修正。核心思路：用 influence function 估计"新到达的延迟标签"对模型参数的边际影响，直接在参数空间做轻量更新，避免全量重训练。方法支持 online 更新节奏，与流式延迟反馈框架（如 TESLA、FNW）兼容。工程信息：参数更新计算量与新到达样本量成比例，相比全量 SGD 显著降低计算开销；无需修改模型结构，可插入现有训练框架。部署环境：适配大规模工业广告系统，训练成本显著节省。

业务价值与适配性： 可以让我们在广告 CVR/CVR-post-refund 模型的每日/小时级更新周期中，用 Influence Function 替代全量重训练，节省 GPU 算力同时维持模型新鲜度。借鉴思路（方法论）：与 READER 互补——READER 解决架构问题，Influence Functions 解决再训练效率问题，两者可组合使用于同一 CVR pipeline。

3. 【Google I/O 2026：LiteRT-LM 正式 GA + Qualcomm QNN Accelerator，56 款模型 NPU 推理 <5ms】

  • 评分：A3/5 · I5/5 · S=11 · P1 · 价值类型：成本优化 + 用户体验
  • 来源：Google Developers Blog | developers.googleblog.com/building-real-world-on-device-ai-with-litert-and-npu/ | 2026-05-19（Google I/O 2026）

内容总结（约 150 字）： Google I/O 2026（5月19日）宣布 LiteRT-LM 正式 GA（General Availability），同步发布 LiteRT Qualcomm AI Engine Direct (QNN) Accelerator，取代旧版 TFLite QNN delegate，并全面兼容 MediaTek 与 Qualcomm 两大 SoC 平台。核心工程数据：① 支持 90 个 LiteRT ops，64/72 测试模型可 100% 委托 NPU 执行；② 在 Snapdragon 8 Elite Gen 5 NPU 上，56 款模型推理延迟 <5ms（CPU 仅 13 款达到同水平）；③ FastVLM-0.5B 多模态视觉模型：TTFT 仅 0.12 秒（1024×1024 图像），prefill >11,000 tok/s，decode >100 tok/s；④ NPU 延迟为 CPU 的 1–20%（等效 5–100x 加速）。LiteRT-LM CLI 和 Python API 同步支持 NPU 后端，覆盖 Linux / macOS / Windows。

业务价值与适配性： 可以让我们在 Android 广告 SDK 中，将轻量广告模型（意图分类、素材特征抽取、CTR 轻量头）一键部署至 Snapdragon NPU，延迟压至 5ms 级别，完全满足广告请求生命周期（RTB <100ms）的端侧推理需求。可直接应用（推理部署模块）：LiteRT QNN Accelerator 可替换现有 TFLite QNN delegate，无需改模型结构，只需重新编译与 profiling；LiteRT-LM 的 Python API 可集成到模型上线流水线做部署前验证。

4. 【Qualcomm Snapdragon 8 Elite Gen 5：37% NPU 提速 + 70 tok/s LLM 推理，Android 旗舰新基准】

  • 评分：A3/5 · I4/5 · S=10 · P1 · 价值类型：新能力探索
  • 来源：TechPowerUp / Futurum Group | techpowerup.com/341312 | 2026 Q1（CES 2026 Innovation Award）

内容总结（约 130 字）： Qualcomm 正式发布 Snapdragon 8 Elite Gen 5，2026 年 Android 旗舰机（三星 Galaxy S26 等）主要平台。AI 能力大幅升级：① Hexagon NPU 较前代提速 37%，功耗降低 16%；② AI 吞吐量整体提升 46%；③ 量化 LLM（7B 量化模型）推理速度达 70 tokens/sec，支持端侧 Agentic AI（模型在设备上规划、推理、自校正，无需云端往返）；④ GPU 推理延迟降至 CPU 的 5–70%，NPU 降至 1–20%（与 LiteRT QNN 联合测试数据）。获 CES 2026 Innovation Award（Qualcomm AI Engine）。部署场景：Android 手机 + Windows on Snapdragon PC，面向 on-device Agent 优化。

业务价值与适配性： 可以让我们在 Android 广告 SDK 设备分层策略中，将搭载 Snapdragon 8 Elite Gen 5 的旗舰机单独划为高能力端设备，开启更复杂的端侧 CTR 精排模型（参数量可放大至当前 2x）或端侧 Agentic 广告策略（实时竞价策略推理无需回云）。借鉴思路：70 tok/s + 37% NPU 提速意味着 2026 旗舰线已可流畅运行 3B 参数量化 LLM，端侧素材理解模型（图文）可在 100ms 内完成。

5. 【MNN-LLM（阿里巴巴）：手机端通用 LLM 推理引擎，比主流框架快 8.6x，DRAM-Flash 混合存储】【延迟发酵】

  • 评分：A3/5 · I3/5 · S=9 · P2 · 价值类型：成本优化
  • 来源：阿里巴巴 MNN 团队 / ACM Multimedia in Asia | arxiv.org/abs/2506.10443 | 2025-06（近期技术讨论升温）

内容总结（约 130 字）： 相较 2025-05-25 报道：首次收录，补充工程细节。MNN-LLM 是阿里巴巴开源推理框架 MNN 的 LLM 专用扩展，专为移动设备设计，解决内存不足与推理速度不达标两大痛点。核心技术：① DRAM-Flash 混合存储——模型权重按访问频率分级存储，有效降低峰值内存占用；② 指令集感知权重重排——针对 ARM CPU 指令集和移动 GPU 特性优化计算布局；③ 多核负载均衡 + 混合精度——充分利用大小核架构与 FP16/INT8 混合推理。对比主流 LLM 框架（llama.cpp 等）最高 8.6x 加速。支持 Qwen、Baichuan、Zhipu、LLaMA 等主流模型，iOS + Android 双平台生产验证（阿里巴巴内部）。

业务价值与适配性： 可以让我们在 Android / iOS 广告 SDK 场景中，用 MNN-LLM 替代 llama.cpp 或 llm.cpp 作为端侧 LLM 推理后端，8.6x 的速度提升直接拓宽可部署模型参数量上限，或将已部署模型的延迟从 500ms 级压至 100ms 级。借鉴思路（方法论）：DRAM-Flash 混合存储对内存受限设备（<4GB RAM 的中端机型）有直接价值，可借鉴用于广告端侧 embedding 存储的分级缓存设计。
