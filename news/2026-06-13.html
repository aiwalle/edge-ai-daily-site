1. 【ACM WWW 2026 联邦推荐双论文：SAM 提升 Embedding 泛化 + KE-FedRS 解决数据稀疏——端侧广告推荐核心挑战正面突破】

  • 评分：A/4 · I/3 · S=11 · P1 · 价值类型：收入提升 / 用户体验
  • 来源：ACM Web Conference 2026 | SAM-FedRec · KE-FedRS | 2026-04/05

内容总结（~150 字）： ACM WWW 2026（TheWebConf）发布两篇联邦推荐系统核心论文：① SAM-FedRec——将 Sharpness-Aware Minimization（SAM）优化器引入联邦推荐 embedding 学习，解决联邦场景下因设备数据分布异构导致 embedding 泛化能力下降的问题；SAM 通过同时优化 loss 值与 loss landscape 平坦度，使模型在新设备 / 新用户上的泛化更稳定。② KE-FedRS——通过知识增强（Knowledge Enhancement）缓解联邦推荐的数据稀疏问题：单个设备的用户行为数据极少，直接训练的 embedding 质量低；KE-FedRS 引入外部知识图谱或全局统计作为先验，在不上传原始数据的条件下补充稀疏信号。两篇论文均在真实推荐数据集上验证，具体指标待查看正文。

业务价值与适配性： 可以让我们在端侧广告推荐中做到：① SAM 优化策略直接适用于联邦 CTR/CVR 模型 embedding 层训练，对用户行为稀疏的长尾设备（低活跃用户）提升推荐精度；② KE-FedRS 的知识增强思路可借鉴到广告冷启动场景——将全局广告统计（曝光频次、品类分布）作为本地稀疏数据的补充先验，减少端侧冷启动时的推荐崩塌风险。适配性：中期可借鉴思路——ACM DL 正文可今日下载，建议与内部联邦学习 / 隐私计算团队对齐方法论适配性。

2. 【Meta AI Research：On-Device LLMs State of the Union 2026——框架选型矩阵、硬件覆盖现状与端侧 LLM 落地路线图全景综述】

  • 评分：A/3 · I/4 · S=10 · P1 · 价值类型：新能力探索 / 成本优化
  • 来源：Meta AI Research (Vikas Chandra, VP AI Research) | On-Device LLMs: State of the Union, 2026 | 2026

内容总结（~150 字）： Meta AI Research 副总裁 Vikas Chandra 发布 2026 端侧 LLM 全景综述，覆盖框架选型、硬件基准与落地路线。核心洞察：① 框架分化成型——ExecuTorch（离线编译，prefill 优势）vs LiteRT（运行时 JIT，decode 弱持平），前者适合 prefill 密集任务（批量素材评分），后者适合流式生成；② 记忆带宽是核心瓶颈——移动设备 50–90 GB/s vs 数据中心 GPU 2–3 TB/s，差距 30–50×，决定 decode 是内存绑定操作；③ 80% 主流 HuggingFace 端侧 LLM 已有 ExecuTorch 可用导出；④ 基准设备：Galaxy S24+ Llama 3.2 1B INT4 prefill 350+ tok/s，600 token TTFT <2s；⑤ 端侧 LLM 已在 Meta 旗下 Instagram、WhatsApp、Messenger、Facebook 亿级用户规模上生产运行。

业务价值与适配性： 可以让我们在广告端侧推理框架选型中做到：以"prefill 密集 vs decode 密集"为判断轴——广告素材批量语义评分属 prefill 密集，选 ExecuTorch；广告意图流式对话属 decode 密集，两框架差异小，优先考虑平台兼容性。带宽瓶颈分析直接用于广告模型参数量与推理延迟的估算。适配性：今日可参考——综述提供可直接引用的框架选型矩阵，建议纳入内部广告端侧推理技术方案文档。

3. 【MiniCPM-V 4.6：清华系 1.3B 端侧多模态，FLOPs -50%、1.5× token 吞吐，iOS/Android/HarmonyOS 全覆盖】

  • 评分：A/3 · I/3 · S=9 · P1 · 价值类型：成本优化 / 新能力探索
  • 来源：OpenBMB (清华 NLP 组) | HuggingFace MiniCPM-V-4.6 · Pandaily 报道 | 2026-05-11

内容总结（~140 字）： OpenBMB（清华 NLP 组）发布 MiniCPM-V 4.6，迄今参数量最小的端侧多模态大模型之一。核心技术：① 1.3B 参数：视觉编码器 SigLIP2-400M + LLM Qwen3.5-0.8B，总量 1.3B；② FLOPs -50%：基于 LLaVA-UHD v4 技术，视觉编码计算量减半，不损精度；③ ~1.5× token 吞吐：较同规模 Qwen3.5-0.8B 快 1.5×；④ 多模态覆盖：单图、多图、视频理解，支持 OCR、视觉问答、图表解析；⑤ 三端支持：iOS / Android / HarmonyOS，GGUF 格式（llama.cpp 兼容）+ AWQ INT4 量化权重；⑥ Benchmark：OpenCompass、RefCOCO、HallusionBench 上达到 Qwen3.5 2B 级别能力，MMMU / MathVista / OCRBench 与服务端方案持平；⑦ 智慧运算指数（Artificial Analysis Intelligence Index）13 分，较同参数量对手 +30%；免费开源，Apache 2.0。

业务价值与适配性： 可以让我们在广告 SDK 中做到：① 以 1.3B 多模态在端侧对广告素材（图文）做实时品牌安全检测、内容相关度评分、OCR 提取（商品价格 / 促销信息），无需上云；② 1.5× 吞吐提升在 Android 中低端机型（<8GB RAM）上使广告素材理解的端侧实时化更可行；③ HarmonyOS 支持覆盖华为设备广告生态。适配性：今日可行动——GGUF 权重已上传 HuggingFace，可通过 llama.cpp 在 Android 测试设备上即日验证广告图片 OCR + 相关度评估延迟（目标 <300ms）。

4. 【Cactus AI Engine：YC 端侧 LLM 跨平台框架，sub-50ms TTFT，React Native / Flutter / KMP SDK，已支持 Qualcomm / MediaTek NPU 路线图】

  • 评分：A/3 · I/3 · S=9 · P1 · 价值类型：成本优化 / 新能力探索
  • 来源：YCombinator / Hugging Face Blog | Cactus on-device inference · 官网 | 2025-12 / 2026

内容总结（~140 字）： YCombinator 支持的创业公司 Cactus 发布端侧 LLM 推理引擎，主打跨平台、低延迟、轻量 SDK。核心指标：① sub-50ms TTFT：端侧首 token 延迟，无网络往返开销；② 582 tok/s：Mac M4 参考值；③ 76 MB RAM：1.2B 模型内存占用，适合 RAM 受限设备；④ sub-200ms 转录：普通手机语音转文字延迟；⑤ 零拷贝内存映射：模型加载极速，减少冷启动延迟；⑥ 量化范围：FP32 降至 2-bit，灵活适配精度-体积权衡；⑦ SDK 覆盖：React Native、Flutter、Kotlin Multiplatform 原生绑定，覆盖主流广告客户端技术栈；⑧ 模型支持：Qwen、Gemma、Llama、DeepSeek、Phi、Mistral；⑨ 2026H1 路线图：Qualcomm Hexagon NPU + MediaTek / Samsung Exynos 支持、Rust 核心重构。

业务价值与适配性： 可以让我们在广告 SDK 端侧推理中做到：① React Native / Flutter SDK 直接对接广告客户端常用技术栈，无需 JNI 层定制开发，降低广告 LLM 端侧接入成本；② sub-50ms TTFT 满足广告意图识别实时响应 SLA；③ 2-bit 量化 + 76MB 内存占用为低端设备广告场景（运营商定制机、预算机型）提供可行路径。适配性：中期可行动——开源 SDK 可今日评估，建议以 Qwen3-0.6B 为基准模型用 Cactus Flutter SDK 验证广告意图分类延迟，并对比 ExecuTorch 在 Android 上的实测差异；NPU 支持待 2026H2 路线图兑现后再评估生产切换时机。

5. 【AlephZero Labs 生产实测：Android 端侧推理 sub-20ms 达成，CV 模型 6 项基准 + "何时走端侧"决策框架】

  • 评分：A/3 · I/3 · S=9 · P1 · 价值类型：成本优化
  • 来源：AlephZero Labs Blog | On-Device AI Inference in 2026: Sub-20ms on Android, Real Benchmarks, and When to Go Edge | 2026

内容总结（~130 字）： AlephZero Labs 发布 2026 年 Android 端侧推理生产实测报告，覆盖 6 个真实 CV 模型的完整 benchmark 数据与"端 vs 云"决策框架。核心数据（2025 旗舰芯片，$400 Android 机型）：① 目标检测（优化版 YOLO）：12–20ms，INT8 量化，NPU 优先降级 GPU / CPU；② 姿态估计（MoveNet Thunder）：15–25ms；③ 文字识别 OCR（CRNN-based）：10–18ms；④ LLM token 延迟：短上下文 <20ms/token；⑤ 云端往返增加 200–500ms，端侧减少 30–50% 端到端延迟；⑥ 技术栈：INT8 量化 + 框架级优化 + NPU → GPU → CPU 降级策略；文章同步提供"何时走端侧"决策矩阵（按延迟敏感性 × 隐私要求 × 算力开销分象限）。

业务价值与适配性： 可以让我们在广告端侧推理方案设计中做到：① 以 10–20ms 为广告素材 CV 推理（品牌 logo 识别、视频帧质量检测）的端侧 SLA 基准，设计量化策略；② 决策矩阵直接用于广告 SDK 端侧 vs 云侧推理路由策略设计——高价值 / 隐私敏感用户走端侧，低优先级流量走云端以节省设备算力。适配性：今日可参考——benchmark 数据和决策框架可直接纳入广告端侧推理方案 PPT，无需额外实验即可作为工程选型依据。

6. 【智谱 GLM-4.6V-Flash：9B 端侧多模态，128K 上下文，免费 API，国产开源多模态端侧旗舰】

  • 评分：A/3 · I/3 · S=9 · P1 · 价值类型：新能力探索 / 成本优化
  • 来源：智谱 AI / 腾讯云开发者 | GLM-4.6V 开源公告 · ModelScope | 2025-12 / 2026

内容总结（~130 字）： 智谱 AI（zai-org）发布 GLM-4.6V 系列并开源，GLM-4.6V-Flash 为面向端侧 / 本地部署的 9B 轻量版本。核心参数：① 9B 参数：GLM-4.6V（106B-A12B MoE）的本地部署分支；② 128K 上下文：支持长文档 / 长视频段理解；③ 原生 Function Call：视觉模型内置工具调用能力，可直接触发广告系统 API；④ 视觉任务覆盖：图像理解、视觉问答、文档解析；⑤ 成本优势：GLM-4.6V API 定价较上代 GLM-4.5V 降低 50%（输入 1 元/百万 token），Flash 版本完全免费；⑥ 开源协议：Apache 2.0，权重托管于 HuggingFace（lmstudio-community MLX 6-bit 量化版可用）；⑦ 同参数量 SOTA：视觉理解在同规模模型中达最优性能。工程部署：支持 llama.cpp / LM Studio 本地运行，MLX 6-bit 量化版适配 Apple Silicon。

业务价值与适配性： 可以让我们在广告链路中做到：① 用 GLM-4.6V-Flash 在设备本地对广告视频帧做内容安全 + 品类识别（128K 上下文覆盖完整广告视频序列理解），替代云端视频审核 API，降低成本；② 内置 Function Call 使端侧模型可直接触发广告展示 / 竞价 API，探索端侧 Agentic 广告决策原型；③ MLX 量化版覆盖 iOS/macOS 测试设备，可与 Apple Foundation Models 方案并行 A/B 验证。适配性：中期可行动——LM Studio 版本今日可下载本地验证，建议以广告视频标签提取作为第一个端侧 PoC 任务。
