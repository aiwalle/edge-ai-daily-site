本期聚焦：Qualcomm 在 48 小时内完成两项生态级动作——以 $3.9B 收购 Modular（MAX Engine + Mojo，6 月 26 日成交）、扩展 Hugging Face 战略合作，Snapdragon NPU 软件护城河正式启动全面建设；Meta RankGraph-2 首次公开十亿节点图推荐系统的完整生命周期协同设计，为广告检索召回架构提供工业级参考。

1. 【RankGraph-2（Meta，arXiv 2606.18379）：十亿节点图推荐全生命周期协同设计——图构建 + 表征学习 + 实时 Serving 三阶段统一优化，直接对标广告检索用户建模基础架构】

  • 评分：A/4 · I/4 · S=12 · P0 · 价值类型：收入提升 / 新能力探索
  • 来源：Meta AI | arXiv 2606.18379 | 2026-06-16

内容总结（约 140 字）： Meta 发布 RankGraph-2，针对十亿节点规模相似度检索图推荐系统提出"生命周期协同设计（Lifecycle Co-Design）"框架，覆盖三个阶段：① 图构建——十亿实体规模下高效建立关联图；② 表征学习——在图结构约束下训练 embedding，保证线上 serving 时近邻检索精度；③ 实时 Serving——低延迟高吞吐图检索推理路径。通过三阶段联合优化（而非分别独立设计），系统性解决工业推荐系统中"表征训练目标 vs 线上 ANN 检索指标"不一致的核心矛盾。工程信息：Meta 生产系统级别规模，十亿节点；实时 serving 路径明确，适配广告检索召回阶段。

业务价值与适配性： 可以让我们在广告检索/召回阶段做到：以统一生命周期协同设计取代当前"离线训练 embedding + 在线 ANN 检索"的分离架构，系统性消除训练目标与检索指标的 gap，提升 Top-K 召回精度。可借鉴思路：Meta 的协同设计方法论对广告系统中"用户 embedding 更新频率 vs ANN 索引重建成本"的权衡有直接指导价值；结合上期 SCaLRec 端侧语义校准方案，可形成"云侧 RankGraph-2 召回 + 端侧实时校准"的完整端云协同链路。

2. 【Qualcomm × Modular 收购（$3.9B，6 月 26 日成交）：MAX Engine + Mojo 实现端侧推理"一次开发全硬件运行"，直接挑战 NVIDIA CUDA 软件护城河】

  • 评分：A/3 · I/5 · S=11 · P0 · 价值类型：新能力探索 / 成本优化
  • 来源：TechTimes / CNBC / BusinessWire | TechTimes（成交报道） · CNBC（原始公告） | 2026-06-24 宣布，2026-06-26 成交

内容总结（约 150 字）： Qualcomm 以 $3.9B 全股票收购 AI 软件初创公司 Modular，交易于 2026-06-26 正式成交。核心资产：① MAX Engine——AI 推理编译器，无需任何 NVIDIA 供应商库即可将模型优化部署至 CPU、GPU、NPU、ASIC，是首个在架构层面真正规避 CUDA 依赖的挑战者；② Mojo 语言——面向 AI 系统开发的高性能语言（兼容 Python 生态），大幅降低跨硬件推理开发门槛。联合创始人：Chris Lattner（LLVM 发明者、Swift 创始人）+ Tim Davis，团队约 150 人。配套动作：Meta 同期宣布采购 Qualcomm Dragonfly C1000 服务器 CPU（250+ 核 Arm 架构，多代协议），Qualcomm 将 FY2029 非手机业务收入目标上调至 $40B（含数据中心 $15B+）。工程信息：Snapdragon Hexagon NPU 将获 MAX Engine 软件栈加持，预计 H2 2026 集成至开发者工具链。

业务价值与适配性： 可以让我们在广告 SDK 端侧推理路径中做到：MAX Engine 与 Hexagon NPU 深度整合后，广告侧 PyTorch/TF 训练的 CTR/CVR 模型可一键编译至 Snapdragon NPU，省去当前繁琐的 QNN SDK 手动适配工作，将模型从训练到端侧部署的迭代周期大幅压缩。可借鉴思路：短期继续以 LiteRT + QNN Accelerator 为 Android 主路径；中期（H2 2026）关注 MAX Engine 开发者工具集成节奏，将 Mojo 编写端侧推理算子纳入评估，与 ExecuTorch 形成双轨技术储备。

3. 【Representation Curriculum（eBay，arXiv 2606.09891）：多阶段课程训练提升数字市场 Ranking 鲁棒性——CTR/CVR 聚合动态曝光分配，解决排序与分配协同优化难题】

  • 评分：A/4 · I/3 · S=11 · P1 · 价值类型：收入提升
  • 来源：eBay AI Research | arXiv 2606.09891 | 2026-06-03

内容总结（约 130 字）： eBay 提出 Representation Curriculum，将数字市场 Ranking 建模为"动态曝光分配机制"：排序结果不只影响单次点击，而是持续改变用户曝光分布，进而影响长期 CTR/CVR 聚合指标。核心方法：多阶段课程式训练（Stagewise Curriculum Training）——先训练粗粒度表征（鲁棒性优先），再逐步细化排序目标（精度优先），使模型在分布偏移下保持稳健；关键创新是将 CTR 和 CVR 聚合信号作为动态反馈纳入排序训练循环，而非静态标签。工程信息：eBay 生产系统验证，面向电商商品排序；适配大规模稀疏特征的多塔 DNN 结构 + curriculum scheduler。

业务价值与适配性： 可以让我们在广告精排层做到：以 Curriculum 多阶段训练替代单阶段端到端训练——先在粗粒度 CTR 标签上建立鲁棒的 ad embedding 表征，再精调至 CVR 目标，降低数据稀疏对 CVR 模型的负面影响，在新广告 cold-start 场景下尤为有效。可借鉴思路："将排序建模为动态曝光分配机制"的视角同样适用于广告 pacing / frequency cap 优化；Curriculum 的多阶段计算预算分配思路也可与端侧实时排序结合，在设备算力约束下分配不同阶段的推理资源。

4. 【Qualcomm × Hugging Face 战略合作扩展（2026-06-24）：HuggingFace 模型零手动集成上 Snapdragon NPU + 端云 Agentic AI 协同调度框架正式落地】

  • 评分：A/3 · I/4 · S=10 · P1 · 价值类型：新能力探索 / 成本优化
  • 来源：Qualcomm 官方 / BusinessWire / HPCWire | Qualcomm 新闻稿 · HPCWire 报道 | 2026-06-24

内容总结（约 130 字）： Qualcomm 与 Hugging Face 宣布扩展战略合作，三大支柱：① 零手动集成——AI Agent 自动完成 HuggingFace 模型在 Qualcomm 平台的配置、优化和部署，无需开发者手动适配 SDK；② 数据中心整合——Hugging Face 存储与推理服务映射至 Qualcomm Dragonfly 数据中心产品，打通"模型实验 → 生产部署"端到端路径；③ 端云 Agentic AI 协同调度——分布式 AI Agent 框架，智能体可跨设备 NPU 与云端动态编排，基于性能、成本、隐私、延迟多维决策。用户侧：Qualcomm 平台（设备端 + 云端）用户获赠 Hugging Face PRO 权限。工程信息：2026-06-24 宣布；与 Modular MAX Engine 整合后将进一步降低 HuggingFace 模型部署至 Snapdragon NPU 的门槛。

业务价值与适配性： 可以让我们在广告端侧 SDK 中做到：HuggingFace 上的广告意图分类、素材理解开源模型（Qwen2.5、MiniCPM-V 等）可通过 Qualcomm AI Agent 自动优化并部署至旗舰 Android 设备 NPU，将模型 POC 周期从当前 2-4 周压缩至数天。可借鉴思路：结合上条 Modular 收购来看，Qualcomm 软件侧（MAX Engine + HuggingFace 生态 + Mojo）与硬件侧（Hexagon NPU, Snapdragon 8 Elite Gen 5）正形成完整闭环，建议将此视为 Android 广告端侧推理的中长期主路径之一。

5. 【m²LLM（IEEE Transactions on PDS）：四维联合优化端侧 LLM 推理——硬件感知模型定制 + 弹性 Chunk Pipeline + 延迟引导 Prompt 压缩 + 层级资源调度，系统性打破内存-延迟-能耗三角约束】

  • 评分：A/3 · I/3 · S=9 · P1 · 价值类型：成本优化 / 新能力探索
  • 来源：IEEE Transactions on Parallel & Distributed Systems | IEEE Xplore 11075620 | 2026

内容总结（约 130 字）： m²LLM 是专门针对移动设备 LLM 推理的四维联合优化框架，系统性解决逐维优化导致的次优解问题。四个核心组件：① Hardware-aware Model Customization——根据目标设备 NPU/CPU 规格自动裁剪模型结构；② Elastic Chunk-wise Pipeline——将 KV-Cache 序列拆分为弹性块，基于系统负载动态调整 pipeline 策略，避免内存峰值；③ Latency-guided Prompt Compression——推理前基于延迟预算自适应压缩输入 Prompt，减少 prefill 阶段 token 数量；④ Layer-wise Resource Scheduling——按 Transformer 层的计算/访存比动态分配 CPU/GPU/NPU 资源，最大化硬件利用率。工程信息：IEEE Transactions on PDS 正式发表，面向资源受限移动设备；在内存占用、推理延迟和能耗三个维度均有显著优化。

业务价值与适配性： 可以让我们在广告端侧 LLM 推理路径中做到：以 Latency-guided Prompt Compression 在竞价时间窗口（<50ms 预算）内自适应裁剪广告意图理解的上下文长度，动态平衡精度与实时性；Layer-wise Resource Scheduling 对广告 CTR 序列模型多层 Transformer 结构有直接适配性。可借鉴思路：m²LLM 的"四维联合优化"与当前广告 SDK 常见的"单独量化 + 单独剪枝"方案正交——建议在端侧广告模型优化实验中引入联合优化 baseline，与 INT4 量化对比延迟/精度 trade-off。
