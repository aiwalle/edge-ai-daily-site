端智能日报 2026-06-23

本期聚焦：双核驱动——Apple WWDC 2026 正式以 Core AI 取代 CoreML（iOS 27 起统一端侧 LLM 推理 API，支持最大 70B 参数、零云端依赖），标志着端侧推理从框架碎片化走向平台统一；与此同时，广告隐私计算步入系统化落地阶段——Data Clean Room 内差分隐私转化建模（arXiv 2505.14959）与联邦基础模型推荐综述（arXiv 2506.11563, IJCAI-ECAI 2026）为后 ATT 时代广告精度与隐私合规共同开出技术路线图。

1. 【Apple Core AI（WWDC 2026）：CoreML 正式退场，iOS 27 统一端侧 LLM 推理 API——支持 70B 参数、零服务器依赖、开放第三方自定义模型权重】

  • 评分：A/4 · I/5 · S=13 · P0 · 价值类型：新能力探索
  • 来源：Apple Developer / InfoQ | InfoQ 报道 | Apple WWDC26 Session 324 | WWDC 2026（2026-06）

内容总结（约 140 字）： Apple 在 WWDC 2026 正式发布 Core AI 框架，接替服役九年的 CoreML 成为 iOS 27/macOS 默认端侧推理框架。核心特性：①统一 CPU、GPU、Neural Engine 调度的单一 API（仅支持 Apple Silicon 设备：iPhone、iPad、Mac、Vision Pro）；②支持部署范围从 3B 视觉模型到 70B 推理 LLM；③零拷贝 Swift API，推理内存精细控制；④提前编译（AOT）将首推延迟压缩至近零；⑤开放第三方模型权重——开发者可通过 coreai-torch 将任意 PyTorch 模型转换部署，coreai-optimization 提供量化工具；⑥Foundation Models 层同步开放协议，任意第三方 LLM 均可接入，打破此前"仅用 Apple 内置模型"限制；⑦零服务器依赖、零 per-token 云端费用，所有推理本地完成。CoreML 保留用于传统小模型任务，Core AI 专攻生成式 AI。

业务价值与适配性： 可以让我们在 iOS 广告 SDK 中做到：Core AI 统一调度 Neural Engine/GPU，广告意图分类与素材质量评估 LLM 通过同一 API 调用，无需再维护 CoreML + Foundation Models 两套适配层；70B LLM on-device 意味着广告个性化数据从根本上无需出域，为 ATT 后时代的隐私合规提供系统级保障。可直接应用：以 coreai-torch 将现有 PyTorch 广告意图分类模型转换至 Core AI，利用 AOT 编译将广告 SDK 初次加载延迟降至毫秒级；建议在 iOS 27 beta 测试期间同步评估 Core AI 与 ExecuTorch 的跨平台统一封装方案。

2. 【Privacy Preserving Conversion Modeling in Data Clean Room：数据净室内隐私保护转化建模——差分隐私 CVR 框架系统化落地，广告归因隐私化迎关键进展（arXiv 2505.14959）】

  • 评分：A/5 · I/3 · S=13 · P0 · 价值类型：收入提升 / 成本优化
  • 来源：arXiv | arXiv 2505.14959 | 2026-05

内容总结（约 140 字）： Data Clean Room（数据净室，如 Google Ads Data Hub、Meta Advanced Analytics）已成后 ATT 时代广告归因主流基础设施，但其内 CVR/转化建模的隐私保护设计仍是行业难点。本文系统研究在 Clean Room 约束下（数据不出域、仅交换聚合/加噪结果）训练转化预测模型的完整方法：①提出适配 Clean Room 隐私预算的差分隐私（DP）训练框架；②设计跨平台环境下转化标签安全对齐机制——解决广告主侧曝光记录与媒体侧转化数据 Join 时的隐私泄漏问题；③在工业级广告数据集上验证，CVR AUC 优于传统 PTQ（后训练量化）基线。工程信息：框架面向云侧 Clean Room 计算节点部署，无需端侧化，但与端侧差分隐私体系（如 Apple SKAdNetwork、Google PAAPI）天然兼容，可作为端云协同隐私计算链路的云侧组件。

业务价值与适配性： 可以让我们在广告转化归因中做到：在 iOS ATT / Android Privacy Sandbox 约束下，通过 Data Clean Room 框架安全聚合广告主转化数据而无需用户级数据出域，即可训练精准 CVR 模型；对内容流媒体平台的付费转化（如订阅购买、VIP 开通）归因尤为直接适用。可直接借鉴思路：DP 训练 + 标签安全对齐机制可用于我们与广告主的 Clean Room 合作协议设计；建议结合 KDD 2026 AdKDD Workshop 评估将本框架纳入下半年隐私广告技术路线图。

3. 【Personalized Federated Foundation Models for Privacy-Preserving Recommendation：联邦基础模型 × 个性化推荐系统综述——IJCAI-ECAI 2026 Survey Track 入选（arXiv 2506.11563）】

  • 评分：A/4 · I/3 · S=11 · P1 · 价值类型：用户体验 / 新能力探索
  • 来源：arXiv（IJCAI-ECAI 2026 Survey Track）| arXiv 2506.11563 | 2026-06

内容总结（约 130 字）： 本文是迄今最系统的"个性化联邦基础模型 × 推荐系统"综述，入选 IJCAI-ECAI 2026 Survey Track。四大核心融合范式：①联邦微调（Federated FineTuning）——端侧 LoRA 本地训练，仅上传差量；②联邦提示（Federated Prompting）——个性化 Prompt 学习，零梯度泄漏；③联邦蒸馏（Federated Distillation）——云侧大模型知识蒸馏至端侧小模型，无需共享权重；④联邦 RAG——本地知识库不出设备。隐私机制覆盖差分隐私、安全聚合、同态加密；工程优化覆盖梯度压缩、异步聚合、系统异构性处理。综述面向移动设备资源约束场景，含边缘推理延迟与通信开销分析，提供多种隐私-精度 Pareto 路径对比。

业务价值与适配性： 可以让我们在广告个性化与隐私合规中做到：以联邦基础模型微调替代集中式用户 embedding 训练——用户行为数据不出设备即可持续优化广告个性化模型，直接满足 GDPR/CCPA 合规要求。联邦提示范式尤其适合推荐 LLM 意图改写场景（端侧生成广告 Query 扩展词）。可借鉴思路：论文中联邦蒸馏框架（端侧小模型 ← 云侧大模型知识蒸馏）与我们现有端云协同架构高度吻合——建议精读第 3-4 章，评估将现有云侧精排 CTR 模型知识蒸馏至端侧轻量版本的工程可行性。

4. 【Google LiteRT-LM + Gemma 4 MTP + QAT【进展更新】：端侧 LLM 推理 2.2x 提速 + QAT 后 E2B 内存降至 1GB，移动端生成式推理确立主流地位】

  • 评分：A/3 · I/4 · S=10 · P1 · 价值类型：成本优化
  • 来源：Google Developers Blog / InfoQ | InfoQ LiteRT-LM MTP 报道 | Google Gemma 4 QAT Blog | 2026-06
  • 相较 2026-06-20 报道（Gemma 4 E2B 基准横评）新增：LiteRT-LM MTP 原生支持（2.2x 提速）+ QAT 检查点（1GB 内存，MTP 加速保留）+ Swift/JS 新 API

内容总结（约 140 字）： Google 在 6 月连续更新 LiteRT-LM（专为 LLM 设计，区别于面向传统 ML 的 LiteRT）与 Gemma 4 模型：①LiteRT-LM 增加 Gemma 4 Multi-Token Prediction（MTP）原生支持，Gemma 4 E4B 推理提速 2.2x，E2B 提速 1.6x；Android GPU（OpenCL）达 52 tok/s，iOS Metal 达 56 tok/s，MacBook WebGPU 达 76 tok/s；与 llama.cpp/MLX/ONNX 对比，prefill+decode 综合快 1.8–3.7x；②Gemma 4 QAT（量化感知训练）检查点同步发布，E2B INT4 量化内存压缩至 1GB（VRAM 减少 72%），且 MTP 加速在 QAT 后完整保留；③新增 Swift 和 JavaScript API，支持 Android/iOS/Web/IoT 跨平台部署。Gemma 4 E2B QAT 格式专为移动端优化，纯文本任务可低于 1GB 内存运行。

业务价值与适配性： 可以让我们在广告意图分类与端侧 LLM 推理中做到：Gemma 4 E2B @ 1GB + MTP 2.2x 加速使旗舰 Android（8GB+）设备部署端侧广告意图 LLM 切实可行，首 token 延迟压缩至对话广告场景可接受范围。可直接应用：LiteRT-LM 与 ExecuTorch 目前是端侧 LLM 两大主流框架，针对 Android + iOS 双平台，建议将 Gemma 4 E2B QAT 与 MobileMoE（Meta）做横向 benchmark；Swift API 的加入使 iOS 广告 SDK 集成门槛大幅降低（无需 C++ 桥接）。

其他观察

本期呈现三条清晰趋势：①平台统一化——Apple Core AI 将 iOS 端侧推理整合为单一 API，与 Google LiteRT-LM 生态共同推动端侧 LLM 框架标准化，移动端 AI 部署成本预计显著下降；②隐私计算系统化——Data Clean Room CVR 框架与联邦基础模型推荐综述标志着"端侧隐私 AI"从技术探索走向工程路线图阶段，后 ATT/Cookie 时代广告精度与合规平衡正在找到落地方案；③推理效率边界持续突破——Gemma 4 E2B QAT @ 1GB / 56 tok/s（iOS）已进入旗舰机可生产级别，端侧广告意图 LLM 的部署时机趋于成熟。
