本期聚焦：WWDC Day 2 开发者会话深挖揭示 Apple AFM-3 关键工程细节（3B 端侧 2-bit QAT + MCP 全平台化），与 Google LiteRT QNN Accelerator 将多模态视觉推理压至 0.12s TTFT 形成共振；Apple / Google / Microsoft 三方同步推进"小模型 + 推理时增强"路线，广告端侧素材理解与意图识别的工程可行性窗口正在快速收窄。

1. 【LiteRT QNN Accelerator + FastVLM 0.5B：Snapdragon 8 Elite Gen 5 NPU 将视觉理解压至 0.12s TTFT，56 款模型 <5ms 延迟】

  • 评分：A/4 · I/4 · S=12 · P0 · 价值类型：成本优化 / 用户体验
  • 来源：Google Developers Blog | Unlocking Peak Performance on Qualcomm NPU with LiteRT | 2026

内容总结（~150 字）： Google AI Edge 与 Qualcomm 深度联合开发 LiteRT QNN Accelerator，替代旧 TFLite QNN delegate，在 Snapdragon 8 Elite Gen 5 上实现以下工程突破：① Attention 原生 NPU kernel——专为 Transformer Attention 层设计 NPU 专属算子，而非通用 delegation，彻底解决矩阵乘单元利用率不足的问题；② 延迟分位数：56+ 款模型 NPU 路径延迟 <5ms（CPU 仅 13 款达标），NPU 整体延迟约为 CPU 基线的 1–20%；③ FastVLM-0.5B 多模态基准：1024×1024 高分辨率图像首字时延 0.12s，预填充 11,000 tok/s，解码 >100 tok/s——0.5B 参数模型首次在移动 NPU 上达成可用级多模态视觉理解；④ Google AI Edge Portal：提供 100+ 热门机型在线基准查询服务，可按设备/加速器/模型配置检索生产目标延迟。硬件平台：Galaxy S26 Ultra / Snapdragon 8 Elite Gen 5，已量产。

业务价值与适配性： 可以让我们在广告素材理解中做到：用单个 FastVLM-0.5B 在用户 Android 设备端以 0.12s 完成广告图片/视频帧视觉特征提取，替代目前云端素材分析管线的前置阶段，延迟从 800ms 降至 120ms 级别，同时数据不离端（隐私合规）。适配性：可直接测试——LiteRT + QNN Accelerator 组合已随 Galaxy S26 量产，建议优先在 Snapdragon 8 Elite Gen 5 设备上验证 FastVLM-0.5B 的品牌/产品/情绪分类精度，作为广告 SDK 创意评分模块端侧原型。

2. 【Apple AFM-3 技术细节揭示：3B 端侧 2-bit QAT + 20B 稀疏云模型 + MCP 全平台化（WWDC Day 2 进展）】【进展更新】

  • 评分：A/3 · I/5 · S=11 · P0 · 价值类型：新能力探索
  • 来源：Apple ML Research / Apple Developer | AFM-3 技术博客 · WWDC26 开发者会话 | 2026-06-08/09
  • 相较 2026-06-08 报道新增：① 3B 端侧模型量化方案确认（2-bit QAT + KV-cache sharing）；② 云端模型架构（20B PT-MoE，动态激活 1-4B 参数）；③ MCP 全平台化 Developer Session 细节；④ AFM-3B MMLU 超越 Qwen-2.5-3B / Gemma-3-4B / Gemma-3n-E4B；⑤ Apple 官方确认模型完全自研，无 Gemini 权重

内容总结（~140 字）： WWDC Day 2 开发者会话与 Apple ML Research 博客同步披露 AFM-3 核心工程细节：① 端侧 3B 模型：采用 2-bit QAT + KV-cache sharing 压缩，iPhone 15 Pro 上约 30 tok/s，无需 API 成本；② 云端 AFM-3 Core Advanced（20B 稀疏 MoE）：基于 Parallel-Track MoE 架构，按请求复杂度动态激活 1–4B 参数，同时实现大模型能力与小模型算力；③ 精度表现：AFM-3B 在 MMLU / MMMLU 上超越 Qwen-2.5-3B、Gemma-3-4B、Gemma-3n-E4B；④ MCP 全平台化：Developer Session"MCP in Apple platforms"宣布 MCP 协议成为 iOS/macOS/Siri 系统级标准接口，"Meet agentic coding in Xcode"开放 IDE 内 MCP Agent 开发；⑤ 模型支持图文多模态输入，natively multimodal（音频/图像/工具调用），所有权重完全自研。

业务价值与适配性： 可以让我们在 iOS 广告 SDK 中做到：① MCP 协议接入用户意图信号——Siri/Agent 触发用户动作时，广告 SDK 通过标准 MCP 接口获取系统级意图信号，升级竞价实时特征；② FoundationModels.framework 零成本素材分析——AFM-3 多模态 API 可直接对广告图片/视频帧做质量评估，无需自带模型；③ 2-bit QAT 路线复用——苹果与腾讯同期独立采用 QAT 实现 2Bit 量化，产业收敛信号明确，广告轻量模型可启动同等量化方案评估。适配性：今日可行动——从 iOS 27 Beta 1 测试 FoundationModels 多模态 API（图片输入、工具调用延迟）。

3. 【Microsoft EuroSys '26：手机 NPU 推理时计算扩展——19× GEMM 加速 + 小模型对齐大模型精度（arXiv 2509.23324）】

  • 评分：A/3 · I/4 · S=10 · P1 · 价值类型：成本优化 / 新能力探索
  • 来源：Microsoft Research / EuroSys '26 | arxiv.org/abs/2509.23324 | 2026-04-26

内容总结（~140 字）： 微软研究院在 EuroSys 2026（欧洲顶级系统会议）发布端侧 LLM 推理系统，首次将 test-time compute scaling（推理时计算扩展）引入 Qualcomm Hexagon NPU：① 核心问题：移动 NPU 的矩阵乘单元在标准 LLM 推理中存在空闲（underutilized），同时缺乏细粒度量化和通用计算（Softmax）的硬件原生支持，使 beam search、迭代验证等 test-time 技术无法高效运行；② 系统设计：端到端 LLM 推理系统，针对 Hexagon 架构实现混合精度 GEMM 调度 + Softmax 专用 NPU kernel；③ 关键性能：混合精度 GEMM 加速 19×，Softmax 加速 2.2×；④ 核心结论：小模型（如 1B INT4 量化）通过 test-time scaling 可在精度上对齐更大参数模型，建立新的"端侧性能 vs 算力成本 Pareto 前沿"；⑤ 目标硬件：Qualcomm Hexagon NPU（Snapdragon 8 Elite 系列）。论文发表于 ACM EuroSys '26。

业务价值与适配性： 可以让我们在广告端侧推理中做到：用 1B 量化小模型 + test-time scaling（多候选生成 + 自验证）在端侧 NPU 上实现接近 3B 模型的 CTR/意图识别精度，同时内存减少约 2/3；Hexagon NPU 19× GEMM 加速也使自回归特征生成在广告 SLA 内变得可行（目标延迟 <50ms）。适配性：中期跟踪——当内部广告模型从 2B 以上参数向 1B 量化迁移时，此方案是精度补偿的重要候选路线，建议在端侧广告模型量化路线图评估中纳入 test-time compute 选项。

  • 来源：新浪科技 / 未来半导体 | 新浪：豆包付费化探索 · 未来半导体：豆包手机 Gen 2 | 2026-06

内容总结（~100 字）： 字节跳动豆包日活突破 1 亿，第二代豆包手机正式与中兴努比亚联合研发（中兴负责硬件，豆包专注 AI 能力），核心架构为端云协同混合推理：简单日常操作本地 NPU 完成，复杂推理任务路由至云端大参数模型。字节计划于 6 月底上线豆包付费内容服务，探索以订阅制覆盖持续增长的端侧算力与云端算力成本。硬件合作扩展至 AI 眼镜、AI 耳机（已开始与其他手机厂商洽谈），复制端云协同架构至多形态终端。豆包 AI 助手已通过系统级调度绕过传统 App 流量入口，对广告竞价模式产生结构性冲击。

业务价值与适配性： 可以让我们在广告系统中认知到：当 AI 助手通过系统级意图执行绕过 App 广告展示层，传统展示/信息流广告的流量池将被侵蚀；字节豆包的商业化转型（DAU → 订阅付费）提示广告算法团队关注"Agent 拦截广告流量"这一长期趋势。适配性：战略观察——建议将 Agent-native 广告接入（类似 Siri MCP 接口）列为广告系统 2027 年规划议题。
