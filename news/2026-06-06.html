内容总结（~140 字）： Bloomberg 记者 Mark Gurman 于 WWDC 前夜（6月5日）发布完整预览，披露三项此前未公开的核心细节：① Siri"Campo"改版——全新聊天机器人风格交互界面，支持语音+文字双通道自然对话，UI 风格类 ChatGPT/Claude；② $10 亿/年 Gemini 协议——苹果为 Siri 云端推理能力采购 Google Gemini 约 1.2 万亿参数定制版，本地轻量模型处理日常任务、复杂推理走 Private Cloud Compute + Gemini；③ CoreAI 向第三方 AI Agent 开放——第三方开发者可将自定义 AI Agent 集成进 Siri 调度系统，Foundation Models 框架预计扩展多模态能力。iOS 27 开发者 Beta 将在 6月8日 keynote 后立即开放，包含 CoreAI SDK。

业务价值与适配性： 可以让我们在 iOS 广告 SDK 开发中做到：在 CoreAI 框架下直接将内部轻量 CTR/意图识别模型集成至 ANE（A18/A19 Pro），同时通过 Siri AI Agent API 探索广告意图识别链路的系统级接入路径。适配性：明日等待正式 API——建议 6月8日 keynote 后第一时间下载 iOS 27 Beta，重点测试三件事：① CoreAI 对自定义模型架构的格式支持度；② Foundation Models 多模态 API 在素材理解场景的延迟；③ SKAdNetwork v5 归因规则变化对广告转化链路的影响。

2. 【Google Gemma 3n：MatFormer 架构端侧 E4B/E2B 动态切换，移动端首次响应提速 1.5×，原生多模态可离线运行】

  • 评分：A/3 · I/4 · S=10 · P1 · 价值类型：新能力探索 / 成本优化
  • 来源：Google DeepMind / Google Developers Blog | Gemma 3n 官方介绍 · DeepMind 页面 | 2026

内容总结（~140 字）： Google DeepMind 发布 Gemma 3n，专为手机/平板/笔记本设计的移动优先模型系列。核心技术创新：① MatFormer 架构——单个 E4B 部署模型内嵌套 E2B 子模型，推理时根据设备负载和任务复杂度在 E4B/E2B 之间动态切换，无需重新加载模型；② Per-Layer Embedding（PLE）缓存——参数按层缓存，大幅降低有效内存占用，实测比 Gemma 3 4B 内存减少显著；③ 移动端首次响应提速 1.5×——相比 Gemma 3 4B 同等质量配置；④ 原生多模态——同时支持音频、图像、文本和视频帧理解，均可本地离线运行；⑤ KVC 共享 + 激活量化进一步压缩推理 KV Cache 开销。权重通过 LiteRT-LM 框架在 Android/iOS 部署（与 6月3日 LiteRT-LM 生产矩阵披露形成闭环）。

业务价值与适配性： 可以让我们在广告素材理解中做到：用单个 Gemma 3n E4B 模型同时处理图片、视频帧和文字广告素材的多模态特征提取，E4B/E2B 动态切换自动适配旗舰/中端设备，一套部署方案覆盖更宽设备谱系。适配性：可直接测试——LiteRT-LM 框架已 GA，与 6月3日报道的 LiteRT 生产矩阵（Android GPU 52 tok/s）配套；优先验证 E2B 路径在中端 Dimensity/Snapdragon 7 系设备上的多模态理解延迟是否满足广告素材扫描场景（目标 <100ms）。

3. 【联邦学习进入移动广告量产阶段：设备调度 / 安全聚合 / 链路追踪工具链成熟】

  • 评分：A/3 · I/2 · S=8 · P2 · 价值类型：用户体验 / 新能力探索
  • 来源：Medium / Praxen | 原文链接 | 2026

内容总结（~120 字）： 行业观察文章综述联邦学习在 2026 年从"研究玩具"到"生产可用"的关键跃迁。工程层面的决定性变化：① 设备调度器（device scheduler）——按设备电量/连接状态/模型版本智能分批聚合；② 安全聚合协议（secure aggregation）已有开箱即用实现（TFF、PySyft 2.0），不再需要自研密码学组件；③ 差分隐私 + 链路追踪（lineage tracking）提供可审计的隐私预算管理，满足 GDPR/CCPA 合规要求。结论：端侧模型训练的三大工程障碍（调度、安全、可观测性）同时成熟，使 FL 成为"避免数据集中的最省力路径"。背景引用：Feynman（IEEE，移动 App 推荐联邦广告平台）验证了 FL 在广告推荐中的工业可行性，并在 ROI 和转化率上均有提升。

业务价值与适配性： 可以让我们在广告用户建模中做到：将 CTR 模型的增量训练下沉到用户设备端，用本地行为数据更新个人化参数而无需上传原始日志，在后隐私监管时代（App Tracking Transparency / GDPR）维持模型新鲜度。适配性：工具链已可调研——建议评估 TFF 2.0 或 Flower 框架作为 FL 训练协调层，结合 ExecuTorch 端侧推理闭环，构建"端侧个性化 CTR 模型"MVP，延迟和精度目标设定参考 Feynman 论文指标。

4. 【ACM IoT 期刊：量化 LLM 端侧推理能效实证——91.2% 精度 + 50% 内存节省 + 延迟 150→110ms】

  • 评分：A/2 · I/3 · S=7 · P2 · 价值类型：成本优化
  • 来源：ACM Transactions on Internet of Things | doi.org/10.1145/3767742 | 2026

内容总结（~110 字）： ACM IoT 期刊发表端侧量化 LLM 综合评测，覆盖能效、精度与推理延迟三维度。关键工程数据：① 精度保留：INT8/INT4 量化后精度保留 91.2%（相对未量化基线）；② 内存节省：模型内存从 500 MB 降至 250 MB（-50%）；③ 延迟改善：推理时间从 150ms 降至 110ms（-27%）；④ 能效优化：在 IoT/边缘设备上量化模型单次推理能耗显著降低，适合电量受限场景。研究覆盖多种主流端侧 LLM 和量化方案（GPTQ/AWQ/GGUF），结论与 ExecuTorch/Vikas Chandra 综述（已报道）高度一致：INT4 量化是当前量产最优平衡点。

业务价值与适配性： 可以让我们在广告端侧模型中做到：以 INT4 量化为基准设计实验，预期可将 CTR 推理模型内存减半（如从 200MB 降至 100MB），同时延迟改善约 25%，直接扩展可部署设备范围（6GB RAM 手机覆盖率提升）。适配性：可借鉴实验设计——将 150ms→110ms 的改善路径作为内部量化实验的 benchmark 目标，研究的三维评测框架（能效/精度/延迟）可复用为我们端侧广告模型量化决策的标准流程。
